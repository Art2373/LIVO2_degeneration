# 运行、参数与回归

## 输入与模型

- `launch/m3dgr_input.launch`：标准 compressed 插件解码 RGB，固定 CameraInfo 跟随实际图像身份；不改变传感器时间。
- `launch/fusion_model.launch`：给定融合参数服务及独立日志会话；记录来源、版本、应用时间和有效性。
- `launch/mapping_m3dgr.launch`：本工程节点 `fusion_mapping`、独立日志输出目录及管理参数。

相机内参为 640×480 全分辨率 K，前端缩放一次。给定 M3DGR 时间补偿按配置应用一次，不在解码或 CameraInfo 中再次添加。外参方向、输入话题和设备族必须一致；更换数据不是改话题即可适配。当前任务不消费深度，不启用深度插件或深度 SDK。

优先使用 README 的注册和串行回归入口，它会建立单一独立 master、单一播放器，记录实际参数、进程、输入身份与退出状态。请选空闲 `--port`；不要 kill 其他 ROS 任务。数据文件必须显式传入。计划和每个运行目录独占创建，已有结果不会覆盖。

## 固定四组

| 组 | 输入构造 | 参数服务 | 固定事件 |
|---|---|---|---|
| H | 原始 RGB | 正常 | 无人工故障 |
| R | 暂停 RGB 送达，LiDAR/IMU 继续 | 正常 | +43–51 传感器秒 |
| B | RGB 像素替换为黑图，其他元信息不变 | 正常 | +43–51 传感器秒 |
| S | 相机正常 | 停止后新会话重启、参数数值不变 | +43–51 传感器秒 |

所有组半速，从 bag 起点至自然 EOF，+15 传感器秒允许模型接入，EOF 另观察 3 墙钟秒。故障/恢复命令、实际图像身份、首次消费、首次信息提交和持续确认分别记录；不得把墙钟、/clock 和图像时间混作同一起点。

## 指标和边界

A 是历史有限保留事件，B 是最终保留路径具有位姿信息并有限提交，C 是实际管理器成功计票。B 不称为视觉健康率。共同持续条件为连续至少 3 次 B，跨度至少 0.2 修正图像秒，模型应用和撤回重置确认。FUSING 单列，不替代实际更新证据。

恢复前没有持续提交，则该次融合中断恢复事件未暴露。黑图实际送达不等于必然造成所有类型退化；以实际测量信息与提交事实判断。完整 EOF 不等于恢复成功；计划观察结束时仍未处理的数据明确保留。

运行器发生非零退出、输入或注入错误时停止后续组。保留失败目录，不修改完成标记或覆盖日志；涉及修复的重测需新登记。部署者应首先核查拆分、命名、依赖和环境差异，不通过调整阈值掩盖迁移错误。
