# 验证范围与已知限制

本工程的验证对象是实际 LIO 处理连续性、输入/模型边界、视觉信息反馈与撤回恢复功能。视觉更新次数、信息提交次数和状态转换都不等于定位精度。

已有开发与归档证据支持：在 Wheel-float01 给定融合参数条件下，已修复前端可在指定 RGB 断流期间继续处理 LiDAR/IMU；零视觉信息的历史保留事件不再刷新管理器成功；真实新图上的连续信息提交可用于恢复确认。健康输入仍存在自然撤回；减少错误成功刷新同时可能增加恢复等待、探测或切换代价。

已观察到的限制：

- Retail/AVIA 管理开启的健康迁移没有建立持续信息提交；管理关闭对照提示运行干预与该配置存在兼容问题，不能据此宣称唯一原因是缓存。
- 分散探测预算产生健康输入额外代价；保留历史参考候选增加单次信息提交但仍未达到持续条件。因此两者未进入生产入口。
- 部分归档运行存在逐层未能归因的缺图。EOF 最后待处理图像可能缺未来传感器支持或被过期清理，不能把清空当成已处理。
- 当前版本的真实暂停、1 倍速、严格 ATE/RPE 和普遍跨传感器配置能力未完成验收。半速不能推断实时性。
- 黑图是受控极端像素故障，不能代表所有图像退化。信息非零仍可能对应错误；反馈改正不能证明每次更新正确。

旧实验与本次独立构建的迁移回归分别保存。新构建只有在完成实际输入、加载库、A/B/C 三层计数、边界和自然 EOF 检查后，才能认定对应功能已验证。各组一次是功能回归，不是统计显著性或泛化试验。详见发布附带的迁移验证摘要；未运行项不能借用历史成绩补齐。
